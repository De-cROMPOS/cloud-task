## Теперь про балансировщик

#### Запуск:

Докера нет, потому что кроме дефолтного редиса и гошки ничего не использую. Мейкфайла тоже нет, но зато есть скриптик ```run.sh```, которому скорее всего нужно выдать права ```chmod +x run.sh```. Если не хочется с ним, то в самом низу команды напишу, чтобы заработало.

Можем запускать его: ```./run.sh``` и он выводит список доступных команд. Порядок должен быть примерно таким:
- ```./run.sh redis``` - запускает редис в докере в фоне
- ```./run.sh imitator``` - запустится гошная программа, которая по введеному числу создаст сервера (localhost:8081, localhost:8082 ... localhost:80xx). Нужно, чтобы балансировщику было куда переадресовывать запросы
- ```./run.sh main``` - запустит основную программу. С ней можно пообщаться через какой-нибудь постман, но я общался курлами:
	- Для создания RateLimiter: ```curl -X POST -H "Content-Type: application/json" -d '{"api_key":"test123","capacity":100,"rate_per_sec":10}' http://localhost:8080/clients```
	- Для удаления RateLimiter: ```curl -X DELETE "http://localhost:8080/clients?api_key=test123"```
	- Для запроса к нашему балансировщику: ```curl -H "api-key: test123" http://localhost:8080/```

Собственно говоря с запуском программы закончено, но можно позапускать еще бенчмарки, тесты и генератор покрытия.  
- ```./run.sh bench``` - Запустит бенчмарки по памяти и времени (Кстати для того, чтобы бенчмарки заработали надо еще и ```./run.sh imitator``` запустить и хоть сколько-нибудь серверов ткнуть)
	- Чтобы поглядеть, что вообще сделали бенчмарки: ```go tool pprof tests\benchmarks-output\balancerCPU.out``` ну или вместо balancerCPU любой другой файлик.
	- Дальше вводим ```list funcname``` только вместо funcname название интересующей функции.
- ```./run.sh test``` - тут запускать имитатор не надо
- ```./run.sh coverage``` - генерит html файлик с покрытием, удобно поглядеть можно
 
По функционалу вроде как всё.

## Описание проекта

### Балансировщик:

Сделал RoundRobin, адреса для перенаправления подбирает динамически из config/cfg.json (делает это в отдельной горутине каждые 30 секунд, если данные будут некорректны, то выведет это и продолжит работу со старыми, если данные корректны, то загрузит новые и удалит неиспользуемые). HealthCheck реализован непосредственно перед выдачей сервера (к нему делается подключение и если сервер не отвечает, то на него вешается фриз на минуту). Ну а в остальном всё работает асинхронно(хэлфчек только тормозит жестко весь процесс судя по профилированию), но тут как вариант использовать фоновый чекер, но откуда тогда будет гарантия, что он успел проверить сервер для выдачи прямо перед отправкой. Также реализован Graceful Shutdown.

### Rate-Limiter:

Тут я выбрал путь делать всё через Redis потому что обычные sql будут долгими. За ключ взял api ключ, в значениях лежат максимальная емкость, количество прибавляемых токенов в секунду и текущее количество токенов(изначально токенов выдается максимум, то есть = емкости). Для операций с бд написаны луа скрипты тк с ними удобно (выполняются как транзации => не будет конфликтов). Также согласно ТЗ был написан тикер, который пополняет всем токены каждую секунду. Он тоже крутится просто в отдельной горутине. Вот тикер тоже долгий судя по профилированию, я бы рассмотрел просто хранение времени предыдущего обращения к редисклиенту и высчитыванию количества токенов при следующем обращении, но в задании выделили именно тикер.

### Обещанные команды для запуска:
```docker run -d --name my-redis -p 6379:6379 redis``` - запуск редиса в докере
```go run .\servers-imitator\imitator.go``` - запуск имитатора
```go run .``` - запуск основной программы
```go test -bench=BenchmarkBalancerWithClientSetup ./tests/benchmarks_test.go -cpuprofile="./tests/benchmarks-output/balancerCPU.out" -memprofile="./tests/benchmarks-output/balancerMEM.out"``` - запуск бенчмарка балансировщика
```go test -bench=BenchmarkCreateAndDeleteClient ./tests/benchmarks_test.go -cpuprofile="./tests/benchmarks-output/balancerCPU.out" -memprofile="./tests/benchmarks-output/balancerMEM.out"``` - запуск бенчмарка для редиса
```go test ./tests/balancer_test.go -v``` - запуск тестов
```go test -coverprofile=tests/coverage-output/cover.out -coverpkg=./... ./tests/... && go tool cover -html=tests/coverage-output/cover.out -o tests/coverage-output/coverage.html``` - запуск генератора для покрытия
